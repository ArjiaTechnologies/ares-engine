# ARES Engine v0.1.0

ARES Engine is an open-source machine-learning trading research and paper-inference engine for ETH market-data experimentation. This first controlled public release focuses on auditable data handling, chronological research, conservative failure behavior, and reproducible software verification.

## Architecture and safety model

- Credential-free Coinbase and Kraken OHLCV ingestion through CCXT, with actual request/page telemetry and strict schema, range, continuity, UTC-grid, quality, alignment, and divergence gates.
- Immutable, manifest-verified multi-venue data generations selected through one atomic pointer, so readers cannot observe a mixed publication.
- Backward-looking feature generation, k-ahead and triple-barrier labels, fixed-length sequences, purged expanding-window folds, and training-fold-only scaling.
- TensorFlow/Keras LSTM and causal residual TCN model families with Optuna study isolation over complete data and material configuration identity.
- Cost-aware delayed long/flat/short backtesting with fees, slippage, stress costs, turnover, exposure, drawdown, trade statistics, and terminal bankruptcy.
- Exact seven-file model bundles, hostile-path and payload checks, runtime-shape verification, atomic champion promotion, and fail-closed paper inference.

ARES does not contain order-routing code, manage balances, require exchange credentials, or operate live capital.

## Installation

Python 3.11, 3.12, and 3.13 are supported.

```bash
python -m pip install ./ares_eth_engine-0.1.0-py3-none-any.whl
ares doctor
ares demo --bars 500
```

For source development:

```bash
git clone https://github.com/ArjiaTechnologies/ares-engine.git
cd ares-engine
uv sync --frozen --extra dev --extra ml
uv run pytest
```

The container runs as a non-root user:

```bash
docker build --target ml --tag ares-engine:0.1.0 .
docker run --rm ares-engine:0.1.0 doctor
```

## Public-ingestion verification

The manual audit workflow contacts only public Coinbase and Kraken endpoints, repeats the same bounded request in isolated storage, reopens the generated Parquet artifacts, verifies request traces and manifests, and recomputes the final verdict. Public endpoint compatibility can change with exchange APIs, CCXT mappings, schemas, rate limits, and retention policies.

## Limitations and security considerations

- This release does not establish profitability, provide investment advice, or demonstrate readiness for live capital.
- Historical performance is not evidence of future results.
- ARES does not implement a locked nested post-search final holdout. Walk-forward scores are model-selection estimates; credible performance work requires a separately locked one-time evaluation and forward paper period.
- OHLC bars cannot establish intrabar ordering or real fills. Fees, slippage, latency, spread depth, liquidity, and market impact remain modeling assumptions.
- `joblib` and Keras deserialization are trust boundaries. Treat model bundles as trusted local artifacts from an authenticated publisher; hashes detect byte changes but do not authenticate authorship.
- Exchange availability, TLS trust, dependencies, host integrity, filesystem durability, and market regimes remain external risks.

## Release artifacts

The GitHub release contains only the wheel, source distribution, `SHA256SUMS.txt`, and a reproducible CycloneDX JSON SBOM. It does not include market data, models, scalers, databases, credentials, private audit bundles, environments, or caches. Nothing is published to PyPI.
